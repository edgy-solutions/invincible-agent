`_load_viewable_case` admits a viewer to a case because they are the recipient of any task on it
(`human_tasks.holds_task_on_case`), and that arm checks none of the case's labels. A recipient
without the label sees the case. The task list has the same gap: it filters on `recipient_id` and
`pending` only. **The leak is open on every deployed release until the per-viewer PR ships.**

The fix is the per-viewer PR (approvals[].task and the task list), the first PR on the train after
0.4.85. It applies the label dimensions as well as the recipient; a task whose object the viewer
cannot see is withheld and recorded as a routing fault, never redacted. ADR-0068 §6.

Done when that PR is merged and rolled, and its seal shows: the holder sees the task and the case;
a non-holder does not; an addressed holder without the label sees neither, and the fault is
recorded; the same holder given the label sees both.
