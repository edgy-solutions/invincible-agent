# The decide-the-meaning-before-the-measurement law

> **Before a measurement runs, write down what EACH possible outcome would mean. Not the expected
> one — each of them.**
>
> **Companion rule: once the stake exists, do not tune the instrument.**

A prediction alone is decorative. *"I expect header-only to dominate"* costs nothing to be wrong
about, because whatever arrives can be narrated into the story the reader brought with them. What
makes a measurement load-bearing is that **every branch was assigned a consequence while its
probability was still unknown.**

## Why the meanings must be written, not just the prediction

A number arriving with no prior expectation gets rationalised. A number arriving against a bare
prediction gets argued about. A number arriving against a **branch table** does one of two things:
confirms, or **surprises** — and the surprise is legible *only because someone said what they
expected first*.

The failure this prevents is interpretation-after-the-fact, which is undetectable from the
outside: the reading is real, the conclusion is plausible, and nobody can tell that the conclusion
was chosen after the number was seen.

## The worked form

From `[[dag-tools-gateway-unverified-subject]]`'s subject-source gauge, written before it ran:

| outcome | decided meaning, in advance |
|---|---|
| `header-only` dominant | the DA path's model is confirmed — M2M bearer carries no user email, so the end user can only arrive by header. A design fact, not a defect. |
| `divergent` non-trivial | the override is load-bearing for real callers → step 2 is a **coordinated migration**, not a config change. **The outcome that changes the plan.** |
| any `token-claim` at all | something already sends user tokens here → the transparent-Jupyter design may be half-built somewhere nobody has looked |
| `header-only` NOT dominant | the stated model of the DA path is **wrong**, and the notebook identity question must be re-asked *before* anything is designed on top of it |

Note what the table does that a prediction cannot: it names, ahead of time, **which outcome would
force a different plan** — and it commits to re-opening a settled question if a specific branch
lands.

re-extraction.

## The companion rule, and why it is not optional

**A prediction with a stake in it is exactly the instrument someone adjusts.** Once "divergent
near zero" is on the record as the outcome that keeps the work small, every ambiguity in the
gauge — what counts as divergent, whether whitespace is a subject, which requests are sampled —
acquires a quiet pull in one direction.

So: **if the reading disagrees, the reading wins.** The prediction exists to make disagreement
visible, not to be defended. Adjusting the instrument after seeing the number is the one move that
destroys the value of having predicted at all.

## The check

Before running a measurement that will inform a decision, answer in writing:

1. What do I expect?
2. **What would each other outcome mean** — specifically, which one would change the plan?
3. **What would I have to UN-DECIDE if the surprising branch lands?**

**Question 3 is the one that bites; 1 and 2 are inventory.** The branches you are relaxed about
cost nothing to write down — you will state them accurately because nothing rides on them. The
branch that would force you to *un-decide* something already settled is the one you are motivated
to find absent, and it is therefore the only branch where the prediction is genuinely
load-bearing.

**Which is why the anti-tuning rule is not a general caution but the specific defense for the
specific branch question 3 identifies.** The pull to adjust an instrument is never uniform; it
concentrates exactly where a reading would reopen settled work. Name that branch first, and the
temptation has an address.

If (2) cannot be answered, the measurement is not yet load-bearing — it is a number being
collected in the hope that it will suggest something. If (3) cannot be answered, nothing is
actually at stake and the prediction is ceremony.
