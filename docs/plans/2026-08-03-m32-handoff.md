**Promise name — RULED, and the design doc §1 is AMENDED to match** (read it
there; this is the summary, the doc is the artifact). The original mechanism
("the step's `id` IS `decision`, so the names are the same string") was off by
a prefix: `f"approval_{step.id}"` with `step.id = "decision"` evaluates to
`approval_decision`, and the `approval_` literal lives in the EXECUTOR, so no
definition content can delete it. As written it produced the exact silent
permanent suspension it was authored to prevent.

The amended mechanism, which is what you build:
    promise_name = step.promise_name or f"approval_{step.id}"
The durable name is DECLARED content, defaulted to today's convention so the
dark-launched `promote_answer_artifact` path stays byte-identical. The `approve`
handler (main.py:1678, same construction at main.py:1631) must honour the
IDENTICAL rule — it resolves what `_run_definition` awaits.
`grouped_review.yaml` declares `promise_name: decision` once the model carries
the field (that is this build's change; build 2 adds the line).

Do NOT rename the handler's literal promise, and do NOT drop the `approval_`
prefix globally — the obvious-looking alternative. Dropping it renames a durable
name on the dark-launched definition path, whose in-flight instances sit OUTSIDE
the grouped-review drain's coverage. A dark-launched path does not announce
itself as live state; it is.

The string-equality guard between awaited and resolved names is part of this
build's definition of done, written RED-FIRST. Under the amended ruling a
CORRECT build makes it GREEN — the names coincide by declaration, which is the
whole point of the fix.

**Guard RED => decision procedure. Follow it; do not reason around it.**
