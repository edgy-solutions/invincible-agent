## 2. The prime hook: one run orphaned by a doc-tools roll in the same minute

The `iagent-prime-substrate` hook (weight 10) launched 22 ontology ingest runs.
- 20 runs reached SUCCESS at about 50 s each.
- `docs_extension` (run `b5798f47`) has been STARTED since its Jena step finished. Its last event is
  "Launching subprocess for sync_jena_ontologies_to_neo4j".
- `docs_corpus` is queued behind it, with two sensor-triggered runs.

**Cause, measured:**
- The run's `repositoryOrigin.repositoryLocationName` is `doc-tools`. Under `DefaultRunLauncher` the
  run worker (pid 1159) lived **inside the doc-tools pod**.
- doc-tools helm revision 38 (09:32 local, doc-tools' own chart) replaced that pod with
  `doc-tools@sha256:0482fd73…`. The new image carries the stateful-node anti-affinity. The old pod got
  `Stopping container` at the same minute as the run's last event.
- No OOM: the user-code cgroup shows `oom_kill 0` and a peak of 293 MB against 2 GiB, and that is not
  the pod anyway.
- The instance config already names this gap. `monitor_started_run` is inert under
  `DefaultRunLauncher`, so a run whose worker dies stays STARTED with no failure event.

**Consequence:** the prime's wait deadline is derived, at 4752 s for 22 entries. When it passes, the
prime exits non-zero, as it must for a partial ingest, and revision 178 is marked FAILED, although
every workload has rolled. (Outcome: see §5.)

**Not done, and why:** marking `b5798f47` canceled is an action on a shared workload, and it was not
taken. Until it is canceled, `docs_corpus` and any future ingest run on the doc-tools location queue
behind it, and so does a re-run of the hook.

**The class:**
- Two lanes rolled two charts into one namespace in the same hour, and one chart's hook depends on a
  process inside the other's pod.
- Nothing serialises the two rolls. 7f's anti-affinity roll was a precondition of this one (10-07
  handoff, item 3), and it landed *during* it.
- Fix proposals: K8sRunLauncher for the doc-tools location (a run gets its own pod), or a
  roll-ordering rule that a doc-tools roll does not overlap an `iagent` prime.

## 3. Engine W identity census, ×3: path parity holds, on a gate that keeps nothing

**Run:** `scripts/probes/engine_w_identity_census.py` inside `deploy/iagent-engine-w`, with
alice, bob and carol plus the probe's own deny control and empty caller. Three repetitions of the
off/on pair.

- **Sandbox serves with `ENABLE_AGENTIC_AUTH=false`** (`enforcement.agenticAuth`, ADR-0025 dark
  launch), and the census correctly refuses to run that way ("a census of nothing").
  - Each run therefore set `ENABLE_AGENTIC_AUTH=true` **in the probe's own process**. The live
    service was not changed.
  - This measures what the gate *would* decide on each path. The live service keeps every chunk.
- **Result, identical in all three runs** (`cmp` of the three diffs):

  ```
  note  60 shared (identity, query, source) decisions, 0 kept by a real identity on both paths
  RED   POPULATION: no real identity kept any shared source; parity on a gate that keeps nothing is parity on a shut door
  ```

- **Why nothing is kept: no document grant can reach a retrievable source.**
  - Engine W's gate asks Topaz `document:<doc_id>#can_read@user:<email>`
    (`agent_fleet/weaviate_expert/service.py:101`).
  - The census retrieved 11 sources: five TM-1H-130H manuals, T.O. 00-20-1, and five MFG-* procedures.
  - Topaz holds 4 `document` objects and 2 `reader` relations. All are alice on `mil#wpn-*`, written
    by hand on 2026-07-06.
  - `DocumentChunk` has **0** chunks whose `doc_id` matches any of them.
  - So no identity is granted any document that Engine W can retrieve.
- **And no git path can grant a document.**
  - `_can_read_document`'s docstring says "asset_grants.yaml → grant_sync". In fact `grant_sync.py`
    manages `MANAGED_GRANT_RELATIONS = [("dataset", "reader")]` only.
  - `policy/asset_grants.yaml` holds three dataset grants and no documents.
  - The two live document relations are bootstrap state that nothing reproduces.

**Fix, for the roll #22 branch:**
- `grant_sync` manages `("document", "reader")`, from an `asset_grants.yaml` entry that carries
  `kind: document`.
- Add one deliberate fixture grant on a retrievable manual, with `granted_by` and a reason, in the same
  form as alice's dataset grants.
- Fold in the two July relations explicitly, so the new prune scope does not revoke them silently.
- Then re-run this census. It is the meaningful one: parity on an identity that keeps something.

Grants are in Lane 1's authority for this lab deployment (Chris, 2026-10-08). They are still written
in git, not into Topaz by hand.
