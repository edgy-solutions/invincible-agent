## What changed

The sandbox runs `67d6e9f6`. This release is `360fbeb6`. `67d6e9f6` is an ancestor of
`360fbeb6`, seven commits back. **No application code, Dockerfile or dependency changed**
between them:

| commit | what |
| --- | --- |
| `9d1dfdf1` | sandbox values: pin cortex-ui to `c390a03`'s digest (roll 206) |
| `642b9e3e`, `9e6ca820`, `b8fd2a60` | docs and session reports only |
| `0b596e33` | chart 0.4.63: version bump, sandbox pins |
| `d6fd6edf` | chart 0.4.64: the topaz-seed job copies all eight policy data files (0.4.63 copied two). Template and test. |
| `360fbeb6` | chart 0.4.65: the domain broker can install from a mirror on a closed network. Template, new values keys (below), and test. |

**Against 0.4.64**, which work was last told to take, the only change is the broker mirror.
`360fbeb6` adds the keys `domainBroker.meshSdkSource`, `meshSdkBaseUrl`, `pip.indexUrl` and
`pip.caSecretName`. With their defaults, the broker installs from GitHub and PyPI exactly as
before.

**Database.** Nothing new since 0.4.62. That chart's BFF added two nullable columns to the ingest
status projection, `retry_reason` and `hold_reason`. The BFF adds them itself at startup
(`ADD COLUMN IF NOT EXISTS`), so no manual migration is needed.

## What a deployment must supply

Names only. No value appears in this note, and none is committed. These are the chart's own
keys. `values-sandbox.yaml`, which ships in the package, is a worked example of a site overlay.

**Refused without it.** The chart will not render unless this is set:

- `meshRegistrar.onBehalfOfUser`: the named owner of the registrar's graph writes.

**Secrets rendered into the `iagent-secrets` Secret.** The committed defaults are lab
placeholders in a public repository. Override every one of them:

| values key | becomes |
| --- | --- |
| `secrets.openaiApiKey` | `OPENAI_API_KEY` |
| `secrets.hfToken` | `HF_TOKEN` |
| `secrets.datahubToken` | `DATAHUB_TOKEN`: a no-expiry DataHub token |
| `postgresql.auth.password` and `postgresql.auth.postgresPassword`, or `externalPostgresql.password` | `BPMN_POSTGRES_PASSWORD` |
| `neo4j.auth.password` or `externalNeo4j.password` | the Neo4j password |
| `fuseki.auth.adminPassword` | `FUSEKI_PASSWORD` |
| `keycloak.auth.adminPassword` | the Keycloak admin password |
| `agentFleet.secrets.*` | one key per entry, for example `SUPERSET_ACCESS_TOKEN` |

There are also 15 Keycloak client secrets, which the BFF and engines use to fetch their tokens:

- `keycloak.dataAnalystClientSecret`, `supervisorClientSecret` and `reviewStarterClientSecret`;
- `keycloak.engineAClientSecret`, `engineDClientSecret`, `engineEClientSecret`,
  `engineOClientSecret` and `engineWClientSecret`;
- `keycloak.caseRunnerClientSecret` and `graphHostClientSecret`;
- `keycloak.planningAgentClientSecret`, `financeAgentClientSecret`, `costAgentClientSecret`,
  `safetyAgentClientSecret` and `docsAgentClientSecret`.

One more, `keycloak.docToolsClientSecret`, creates the doc-tools client in this chart's realm.
doc-tools' own chart must be given the same value. If the two drift, nothing fails loudly:
doc-tools mints no token until authorization is enforced.

**Secrets made out of band and named by the chart.** Each is optional, and applies only when its
feature is on:

| values key | Secret it names |
| --- | --- |
| `keycloak.brokers.openddil.existingSecret` (or `.clientSecret`) | the identity-broker client secret |
| `keycloak.truststore.existingSecret` | the PEM bundle Keycloak trusts |
| `cortexBff.tlsTrust.secretName` | the PEM bundle the BFF trusts |
| `primeSubstrate.caBundle.existingSecret` | the CA bundle for the prime job |
| `topazSeed.policySource.git.authSecretName` | keys `username` and `password`, for a private policy repo |
| `topazSeed.policySource.git.caSecretName` | key `ca.crt`: the CA that signed an internal git host |
| `domainBroker.pip.caSecretName` (**new in 0.4.65**) | key `ca.crt`: the CA that signed the PyPI / SDK mirror. It replaces the public bundle. There is deliberately no skip-verify setting. |
| each ingress's `tls[].secretName` | the ingress certificate |

**Closed network: the domain broker (new in 0.4.65).** The broker pod installs its Python
dependencies and the SDK at start. Without a route to github.com and pypi.org, set:

- `domainBroker.pip.indexUrl`: the internal PyPI simple index (`PIP_INDEX_URL`);
- `domainBroker.meshSdkSource`, either:
  - `url` (the default), which fetches `<meshSdkBaseUrl>/<meshSdkVersion>.tar.gz`. Point
    `domainBroker.meshSdkBaseUrl` at a mirror that holds the GitHub tag tarball
    `v0.9.10.tar.gz` under that file name; or
  - `index`, which installs `iagent-mesh==0.9.10` from `pip.indexUrl`. Upload the sdist, or a
    wheel built from the tag, to that index.
- Leave `domainBroker.meshSdkVersion` at `"v0.9.10"`.

**Image settings the release depends on.** The sandbox overlay carries these, and a deployment
must carry them too:

- `dagster.userCode.image.repository: edgy-solutions/invincible-agent/dagster-control-plane`.
  Otherwise the chart renders `dagster-user-code:0.4.65`, which CI has never built. Both images
  come from the same Dockerfile and use the same command.
- `cortexUi.image.digest`: cortex-ui 0.3.0's digest (above). The default is `:latest`.
- Pin the images the release does not build (next section). The chart defaults for
  `central-gateway`, `user-deployment` and `pub-tools` are `:latest`.
- Mirror the third-party images that are no longer pulled anonymously from upstream. The
  sandbox uses `ghcr.io/edgy-solutions/mirror/electric` and `ghcr.io/edgy-solutions/mirror/mc`,
  and `bitnamilegacy/postgresql`.
- Do not apply `values-roll-frontend-digest.yaml`, which ships in the package. It is an old roll
  overlay that points cortex-ui at another digest. `values-sandbox-litellm-rehearsal.yaml` is a
  sandbox rehearsal overlay and is not for a deployment either.
- Optional: `engineC.enabled: false`. The sandbox does not run `swarms-scraper`. Its
  `:0.4.65` image does exist.

Everything else is site configuration: hosts, issuer, DataHub, the model endpoint and storage.

## How this was verified

Every check was run on 2026-10-23 against the published artefacts:

- **Release assets.** The tgz and `image-digests.json` were downloaded from the GitHub release,
  and their sha256 values are the ones above. The tgz holds no `*.secret.yaml`. The gh-pages
  `index.yaml` lists 0.4.65 with the tgz's digest, at the release URL.
- **Images.** Each of the 19 `:0.4.65` tags, and the matching `:360fbeb6` build tag, was fetched
  from GHCR. Both name the digest in the table. Each manifest's bytes hash to that digest. It is
  an index listing `linux/amd64` and `linux/arm64`, and both children resolve.
- **The checks can fail.** A fake digest, the short commit as a tag, and a tag nobody pushed all
  returned 404. Comparing a real tag against a wrong digest was refused.
- **Bytes versus the sandbox.** 0 of the 19 digests equal the `67d6e9f6` build's digests.
- **The retag preserves the digest.** `imagetools create` with a single source left the digest
  unchanged in 12 of 12 cases checked: four images at each of 0.4.63, 0.4.64 and 0.4.65.
- **Renders.** The packaged tgz rendered on its defaults (with `meshRegistrar.onBehalfOfUser`
  set) and with `values-sandbox.yaml`. The images above are what those renders name.
- **What changed.** `git merge-base --is-ancestor 67d6e9f6 360fbeb6`, and the file list of
  each of the seven commits.

**Not verified.**

- 0.4.65 has not been installed anywhere, and no 0.4.65 image has been run.
- The sandbox's running pod imageIDs were not read, because the sandbox was frozen. "The sandbox
  runs 67d6e9f6's digests" is a claim about roll 206's committed values and its build run.
- The closed-network broker path (`meshSdkSource: index`, `pip.caSecretName`) is covered by the
  chart test only. It has not been run against a real mirror.
- The digests of the two floating images.
